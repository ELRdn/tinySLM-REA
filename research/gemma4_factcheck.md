### 1.3 KV

| モデル | 32K FP16 | 32K INT8 | 128K FP16 |

**チェック:** KV は K と V を別々に数えた保守値。12B 以降は K=V を再利用するが、ランタイムが両方を保存する可能性があるため、あえて 2 倍で計算した。技術レポート Table 3 の 32K KV（E2B +0.05GB、E4B +0.14GB、12B +0.28GB）は、これより小さい。E2B/E4B は約半分で、4-bit KV か K のみの保存を示唆する。**本文に注記済み。**

### 2.1 修正した過剰主張

1. **「E4B は Android 8GB の safe 2.8GiB に収まる」**  
   → runtime +0.35GiB なら 2.62GiB で収まるが、+1.0GiB なら 3.26GiB で nominal のみ。**「nominal、safe は runtime 次第」**に修正（第0章、第6章、第7章、付録F）。

2. **「26B は速度が 4B 級」**  
   → 計算量は active 3.8B で 4B 級だが、重みの読み出しは 26B 分。**「計算は 4B 級、メモリ帯域は 26B」**に修正（第0章）。

3. **「標準の TFLite に三値行列積はない」**  
   → 確認できていないだけ。**「確認できていない【未検証】」**に修正（第12章）。

4. **「12B は iPhone の safe 4.8GiB に収まる」**  
   → +0.35GiB なら 3.87GiB で余裕、+1.0GiB なら 4.52GiB でぎりぎり、+1.5GiB なら 5.02GiB で safe 外。**ランタイム感度を明記**（第6章）。

5. **「12B QAT は iPhone に入らない」**  
   → 32K 6.33GiB だけでなく、4K でも 6.11GiB で 6.0GiB を超える。**4K の数字を追加**（第6章）。

6. **「26B/31B の QAT 総メモリ」**  
   → GGUF サイズ（14.21/18.43GiB）ではなく、LiteRT-LM バンドル（15.46/19.89GiB）に統一。**ランタイムを揃えた**（第6章、付録B）。
